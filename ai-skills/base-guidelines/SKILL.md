# Base Guidelines

这是一套面向 Claude Code 和 OpenAI Codex CLI 的中文基准指南。目标不是“写更多”，而是把常见的 LLM 编码失误压到最低：先想清楚，再动手；只改必要部分；不做多余抽象；给出可验证的完成标准。

## 使用原则

- 禁止跳过 Skill 使用规则直接写代码；在进入实现前，先完成相关 Skill 的评估，并说明为什么采用或不采用它，再继续后续实现。
- 先定验收标准：开始前先明确什么算完成。
- 先查再改：先看现有实现和约定，避免重复造轮子。
- 只保留必要输出：代码、文档、测试都只产出当前任务需要的最小集。
- 先确认再实现：如果需求、边界、输入输出或失败模式不明确，先说明假设或提问。
- 最小改动：只修改直接相关的代码和配置，不顺手重构无关内容。
- 简单优先：能用更少代码完成，就不要引入额外层、额外配置或“未来可能用得上”的结构。
- 只处理真实问题：不要为不可能发生的场景补复杂防御。
- 目标驱动：每次改动都要对应一个可验证结果，必要时先写测试或验证步骤。

## 适用场景

- 写新功能前，先判断是否存在更简单的方案。
- 修 bug 时，先复现再修复，再验证修复结果。
- 做 review 时，优先找出过度设计、隐含假设、无关改动和缺少验证的地方。
- 做重构时，只保留能直接证明收益的变更。

## 执行清单

1. 先说清楚假设、风险和不确定点。
2. 只改与当前目标直接相关的文件。
3. 避免引入新抽象、通用框架或可配置层，除非用户明确要求。
4. 删除因本次修改而产生的无用导入、变量或函数。
5. 给出明确的验证方式：测试、命令、预期输出或人工检查点。

## 结果标准

- 变更范围收敛。
- 代码或文档更容易验证。
- 没有引入多余复杂度。
- 用户可以清楚看到改了什么、为什么改、如何验证。
