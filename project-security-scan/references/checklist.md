# 项目安全审计检查清单

仅在目标项目出现对应技术或部署形态时读取本清单。清单用于避免遗漏，不构成漏洞结论；每项发现仍需满足主流程的证据、攻击前提和可达性要求。

## 服务端入口与授权

- HTTP 路由、中间件、GraphQL resolver、WebSocket/gRPC handler 是否在业务查询前完成认证和资源归属校验。
- 管理、调试、健康检查、OpenAPI、回调和内部接口是否被错误暴露；可信代理和来源头是否有明确边界。
- 租户、组织、用户和资源 ID 是否在每次读写、导出、删除和异步任务中保持一致。

## 数据与外部交互

- 数据库查询、排序字段、筛选表达式、命令、模板和反序列化入口是否对不可信输入施加类型和允许列表约束。
- URL 抓取、Webhook、代理、重定向、图片/文档解析是否限制协议、主机、内网地址和重定向链。
- 上传、下载、解压和对象存储访问是否校验类型、大小、路径、文件名和访问控制；避免以用户输入直接拼接路径。

## Web 与身份状态

- Cookie 的 `Secure`、`HttpOnly`、`SameSite` 和域范围是否与登录流程一致；状态变更接口是否具备适当 CSRF 防护。
- CORS 是否对允许来源、凭证和预检响应实施精确限制；避免把反射来源或通配符与凭证组合。
- 富文本、HTML、URL 跳转、iframe 和前端危险 DOM API 是否有输入净化或域名允许列表。

## 交付与供应链

- Dockerfile 是否使用非 root 用户、最小运行时镜像和明确的生产依赖安装阶段；构建上下文是否排除敏感文件。
- CI/CD 是否避免打印 secrets，依赖安装是否锁定 lockfile，发布令牌是否被限制到最小权限与正确环境。
- 包的安装脚本、原生二进制下载、私有 registry、Git URL 依赖和弃用/接管包是否有来源与完整性风险证据。
- 对直接生产依赖、存在 advisory 的传递依赖和高影响包，核对 `deprecated`、发布与迁移信息、`engines.node`、`peerDependencies`；没有证据时标为“待确认”，而非“受支持”。

## 日志、错误与默认配置

- 日志、异常堆栈、监控标签和审计事件是否泄露凭证、个人信息、内部地址或原始请求体。
- 生产环境是否关闭调试模式、测试账号、宽松限流和不安全的默认 CORS/权限配置。
- 加密、签名、随机数和 TLS 校验是否使用受支持算法与库默认安全配置；仅在代码证据足够时报告问题。
